`linkchar-cms import` no longer replaces what editors wrote without showing it. It first runs the script dry, prints the plan (`Plan for https://…: 3 documents change, 1 created, 11 unchanged, 2 files uploaded.`, then each changed document with its fields, `~ projects "Casa Giv": title.es, gallery`, and each creation with what it looked for) and asks `Write this to <url>? [y/N]` before running the script for real; `--yes` skips the question (CI, `--password-stdin`), `--dry-run` stops after the plan, and a Supabase that is not local refuses to write without `--allow-remote`. The script runs twice, so its own output appears twice. The closing lines say what changed among what it updated (`15 updated (3 changed, 12 unchanged; 14 by key, 1 by slug)`). In the API, `createImportSession({ dryRun: true })` writes and uploads nothing: `upsert()` returns the found document's id, or a `dry-run-…` placeholder for one it would create, with `fields` (the fields that change, empty when the stored content already matches, also returned by a real upsert), and `media()` returns the library file by its bytes or a placeholder item; `summary()` adds `changed: [{ entry, id, title, fields }]`, `unchanged`, `media` and `dryRun`. Content is compared as it would be stored (normalized rich text, item keys), never by text. This comes from a seed run that silently replaced a morning of panel edits.

To update a project: nothing in the script. The seed run against the hosted project now needs `--allow-remote`, and `--yes` in CI; code that reads `summary()` can use `changed` and `unchanged`.
